# 安装与第一次复刻

需要电脑端WorkBuddy、本人麦当劳MCP连接，以及Python 3.10或以上。核心脚本只用Python标准库；当前首选到店自取、无券核价。仅用手机独立云端运行尚未验收。

## 1. 安装技能

在仓库的downloads目录下载mcfuke-validation.zip。电脑WorkBuddy进入“专家·技能·连接器 → 技能 → 添加技能 → 上传技能”，导入ZIP并启用。

新建对话，显式选择mcfuke-validation技能。无需选择开发者的项目目录。可先发送：

> 请加载麦麦复刻技能，说明当前能力和限制；暂不调用麦当劳工具。

项目已在默认工作区验证技能加载和结果展示；不要把仅说“复刻”两个字当作技能已调用的证据。

## 2. 连接本人麦当劳MCP

在WorkBuddy自定义连接器中配置官方服务https://mcp.mcd.cn，传输协议Streamable HTTP。本人Token从https://open.mcd.cn/mcp获取，按客户端私有配置方式填写，不发到聊天、配方或公开仓库。

仓库mcp-config.example.json仅用环境变量占位符，是脱敏参考；占位符是否自动解析以客户端支持为准，不声称直接粘贴就能授权。

连接后可要求宿主调用now-time-info检查。手机可通过同账号连接电脑，选用电脑已安装技能和连接器；这不等于手机独立运行已经验证。

## 3. 导入分享配方

解压downloads/meal-share.zip，得到meal.recipe.json和card.md。把JSON作为附件交给对话；若附件不支持JSON，把它放入当前工作区并提供文件路径。配方不在“上传技能”入口导入。

发送：

> 使用麦麦复刻技能，读取meal.recipe.json并校验，展示预算、份数、餐品与允许替代，让我确认。随后按我选择的门店查询当前菜单、详情与可用券，运行prepare，使用麦当劳MCP执行生成的核价请求，保存回执并运行assess、card。请直接展示生成的结果卡。不可售或超预算时如实停止，不扩大预算、不擅自换菜，不下单、不领券、不发布。

示例是33元、板烧首选/龙焰替代、无糖可乐中杯，仅用于演示目标，并不保证任意门店能在预算内复刻。预算内未找到候选也可能是正确结果。

## 4. 看懂结果

结果卡依次展示复刻结论、餐单与变化、价格与预算、下一步。所选规格没有被服务端回显时保留待核实，不能靠价差推断无糖已确认。卡片是对话中的静态产物，后续操作在对话中继续，没有自动下单按钮。

本地live复核窗口为报价120秒、门店资料600秒，仅是程序策略，不是官方有效期。过期需重查。历史演示必须标记回放，不作为当前有效报价。

卡片含价格和时间；分享可复用目标请使用配方包，不把历史结果卡当成当前可执行餐单。

## 5. 常见问题

- 未找到技能：检查是否导入并启用，在对话中显式选择；MCP连接成功不代表技能已加载。
- 缺少门店：提供城市和附近地标，让官方工具查出门店后自行选择。
- 找不到Python：在终端确认python或python3可用；宿主使用实际已安装解释器，不假称执行成功。
- 没看到结果卡：先看是否仍在等门店或条件；业务处理完成后，要求展示card输出的SVG产物。
- 有适用券：本版未适配有券计价，先说明缺口，再由用户决定是否接受无券比较。
