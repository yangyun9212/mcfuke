# 本轮真实跨门店验证

本技能脚本提供配方校验、请求生成、回执评估、分享包和结果卡。真实调用由WorkBuddy内已连接的麦当劳MCP承担；已取得同账号两店真实核价及默认工作区结果卡展示证据。另一位朋友完成验证来自项目所有者反馈，未取得完整脱敏过程，不推广为全量跨账号验证。

## 开始条件

确认用户提供的就餐方式、预算、商品份数、必须保留项、允许替换项及两个门店。没有实际门店时，按用户城市和位置通过官方工具查候选并让用户选择；不要编造门店编号。位置只用到完成此次查询所需程度。

当前JSON配方的内部格式是 `mcfuke.recipe.v1`，不是麦当劳官方请求体。它的名称、选项不能直接当成官方商品代码或特调参数。样例商品都是虚构的：真实验证要先根据实际菜单建立用户认可的配方，不能把测试SKU传给官方工具。

## 工具核验

从宿主实际暴露的工具取得所需参数和描述。可能用到 `now-time-info`、`query-nearby-stores`、`query-meals`、`query-meal-detail`、`query-store-coupons` 和 `calculate-price`；此列表不是存在性证明，具体以当前工具列表为准。

工具未暴露时停止真实模式，报告缺少连接器；不能用模拟菜单补齐。Token在WorkBuddy私有连接器配置中由用户管理，不要求粘贴进对话或仓库。本包不读取凭据文件、不修改连接器配置。

## 执行

1. 用门店A的本轮可售菜单和商品详情匹配配方。每个选项记录菜单/详情中支持它的依据；不能靠餐品名称猜“无糖”或“无某配料”。套餐需查清组成、子商品、规格与特调。
2. 查询当前门店可用券。v0.1.0只适配无券核价；存在需要使用的券时报告当前适配缺口，由用户决定是否接受无券核价，不删除券字段伪装已支持。不代领券。
3. 按真实schema构造完整候选，调用 `calculate-price`。记录调用对应的门店、就餐方式、餐品规格数量、券、应付总额、原始金额单位、调用时间和工具结果定位。
4. 明确业务拒绝可改用另一个已接受候选，改变后整单重新核价。认证、限流、网络或解析失败时停止本门店后续调用并记录未完成；不能把错误当成0元或沿用旧报价。
5. 对门店B独立重复查询和核价，不直接复制A的SKU、个人券、规格或价格。
6. 并排输出两家店结果。变化可能来自可售餐品、规格、账户优惠或价格；只有证据支持时才给出具体归因。两店完全相同也是有效结果，不制造差异。

## 证据和完成标准

只对当前会话中实际执行的调用称为“本轮真实”。保留客户端版本、日期、工具名、脱敏输入/输出及可追溯的会话定位。宿主不提供调用ID时，用实际消息/步骤位置，不伪造服务端ID。

原始响应可能含个人信息。经用户同意保存到其选定的本地 `*.local.json` 文件；公开仓库只放脱敏摘录。配方格式校验、金额检查或结果中的mode字段均不能认证官方来源，需与原始调用对照。

某门店未跑通时结果是部分完成。两个真实门店都完成核价，只能证明该配方在这两个上下文可用，不能证明跨账号已验证、需求成立或全国可用。下单、支付与订单状态回查不属于本包范围。

真实运行后把遇到的字段差异和报错记录下来，用这些证据实现正式适配器；不要先假设官方响应与本地模拟结构相同。
